This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev          # Vite dev server (http://localhost:5173) — proxies /api/* to localhost:3001
npm run build        # TypeScript check + Vite production build
npm run lint         # ESLint
npm run preview      # Preview production build locally
```

For the API to work in dev, run `vercel dev` in a separate terminal (port 3001). The Vite server proxies all `/api/*` requests there.

```bash
npm run slides:convert   # One-shot PPTX→thumbnail conversion
npm run slides:watch     # Continuous PPTX conversion worker
```

There are no automated tests.

## Architecture

This is a Hebrew-language sales CRM for therapists/coaches, built RTL throughout. It has two layers:

**Frontend** — React 19 + TypeScript + Vite + Tailwind CSS, deployed to Vercel as a SPA.

**Backend** — Vercel Serverless Functions in `api/`, using Supabase (Postgres) as the database and Supabase Auth for authentication.

### State Management

All app state lives in a single `AppState` object (defined in `src/types.ts`) held in `App.tsx`. There is no Redux, Zustand, or Context — just `useState` at the root.

- **Load**: On login, `apiLoadState()` fetches from `GET /api/state` and merges with `SEED_STATE` via `mergeState()`.
- **Save**: Every `setState` call triggers `apiSaveState()` automatically (the `useEffect` at line 236 in `App.tsx`).
- **Seed**: `src/seed.ts` contains the default `AppState` used on first run and as a merge base.

### Auth Flow

Supabase Auth (implicit flow) issues a JWT. The `crm_users` table maps `auth_user_id` (Supabase UUID) → `crm_user_id` (short text like `'u1'`) + role. Access is gated — a user must have their email pre-approved in `crm_users` by an admin before they can log in.

Two roles:
- `admin`: sees and saves all data
- `salesperson`: data filtered to `assigned_to === uid` for leads/tasks/clients

### API Layer (`api/`)

- `api/state.ts`: Main endpoint. GET returns role-filtered `AppState`. POST saves with ownership validation. Contains all DB↔frontend field converters (DB is snake_case, frontend is camelCase).
- `api/_lib/auth.ts`: JWT validation via `supabaseAdmin.auth.getUser()`, returns `CrmUser`.
- `api/_lib/supabaseAdmin.ts`: Service-role Supabase client — server-only, never import in browser code.
- `api/marketing-generate.ts`: Calls Claude API (Anthropic SDK) to generate weekly marketing messages across 5 platforms.
- `api/users/`: Admin-only user management endpoints (create, update, delete, change-password).
- `api/auth/`: Password reset and current-user endpoints.

### Database Schema

`crm_config` (single row, fixed UUID `000...001`): stores all configuration as JSONB columns — users, statuses, products, dropdown options, custom fields, labels, nav config, sales targets, automation rules, table prefs. Only admins write this.

Separate tables for transactional data: `leads`, `activities`, `tasks`, `clients`, `chat_messages`, `pinned_notes`, `courses`, `lessons`, `content_items`, `marketing_knowledge`, `marketing_messages`.

Migration SQL files: `supabase/001_init.sql` (core schema), `supabase-courses-migration.sql`, `supabase-marketing-migration.sql`.

### Key Source Files

| File | Purpose |
|------|---------|
| `src/types.ts` | Single source of truth for all entity types — changes here affect the entire app and API |
| `src/App.tsx` | Root: global state, all entity handlers, automation engine, auth flow, tab routing |
| `src/api.ts` | Frontend API layer: Supabase auth client, load/save state, Supabase Storage helpers |
| `src/seed.ts` | Default `AppState` for first-run and merge fallback |
| `src/utils.ts` | Pure helpers: `uid()`, `calcScore()`, `calcCommission()`, `getHotLeads()`, `openWhatsApp()`, `getL()` (label lookup) |
| `src/ui.tsx` | Shared UI primitives: `Btn`, `Input`, `SelectInput`, `Modal`, `Badge`, `Toggle`, etc. |

Views in `src/views/` correspond 1:1 to nav tabs. `CoursesView` is lazy-loaded (`React.lazy`) because `pdfjs-dist` is large.

### Conventions

**IDs**: All entity IDs are short random text strings generated by `uid()` in `utils.ts`, not UUIDs.

**Status colors**: Stored as hex strings (`#rrggbb`), never Tailwind class names — they go into color pickers.

**Thumbnails**: `ContentItem.thumbnails` stores only Supabase Storage HTTPS URLs. Base64 data URLs are stripped before `apiSaveState` (Vercel has a 4.5 MB body limit). Thumbnails are uploaded to the `course-files` bucket before saving.

**Labels / i18n**: UI strings can be overridden by admins via `state.labels`. Always use `getL(key, state.labels)` (or the `getLabel` wrapper in `App.tsx`) instead of hardcoding strings that should be customizable.

**Automation engine**: `runAutomations()` in `App.tsx` fires on `status_change` and `new_lead` triggers. No-activity automations run once on mount. All automation rules live in `state.automationRules` (persisted in `crm_config`).

**RTL**: The entire UI is Hebrew/RTL. Root div has `dir="rtl"`. Keep this on all new views.

**DB field mapping**: The API layer converts between DB snake_case and frontend camelCase in `api/state.ts` using `dbTo*` / `*ToDb` converter functions. When adding new fields, update both the DB schema and both converter functions.
