# שלב 1 — מה פנחס צריך לעשות

> כ-20 דקות בסך הכל. כל צעד כתוב כ"איפה ללחוץ ← מה אמור לקרות".
> **הסדר חשוב.** צעד 3 (המיגרציה) רק אחרי שצעד 2 (העלייה לאוויר) הסתיים.

---

## צעד 1 — לפני המיזוג: לראות את ההדגמה (5 דקות)

1. בתוך ה-PR ב-GitHub יש קישור **Preview** של Vercel. להיכנס אליו ולהתחבר כרגיל.
2. **מסך הכניסה:** אין יותר כפתור "שלח בקשת גישה". במקומו כתוב "אין לך משתמש? פנה למנהל".
3. **הגדרות ← משתמשים:** בבחירת תפקיד יש ארבע אפשרויות: מנהל, ניהול משרד, נציג מכירות, מזכירות.
4. **"👁️ צפה כ..." על נציג:** בשורת הלשוניות רואים רק ראשי, לידים, משימות וצ'אט.
5. אם הכל נראה נכון, לאשר את ה-PR.

> ⚠ ה-Preview מחובר למסד האמיתי. מסתכלים בלבד, לא משנים נתונים.
> ⚠ לפני המיגרציה (צעד 3) **אי אפשר עדיין לשמור** תפקיד "ניהול משרד" או "מזכירות". המסד ידחה את זה. זה תקין.

---

## צעד 2 — מיזוג ועלייה לאוויר (2 דקות)

1. ב-GitHub: **Merge pull request**.
2. לחכות כ-2 דקות עד ש-Vercel מסיים לפרסם.
3. להיכנס למערכת הרגילה ולרענן את הדף. אמורים לראות את מסך הכניסה החדש.

> ה-PR הזה כולל גם את התיקון לאיבוד הנתונים (PR מספר 4). אחרי המיזוג, PR 4 ייסגר לבד או שאפשר לסגור אותו ידנית.

---

## צעד 3 — מיגרציה אחת במסד (3 דקות)

1. **Supabase ← SQL Editor ← New query**
2. לפתוח את הקובץ `supabase/migrations/2026-10-21_stage1_security_roles.sql`, להעתיק את **כל** התוכן ולהדביק.
3. **Run.** אמור להופיע `Success. No rows returned`.
4. **בדיקה:** בסוף הקובץ יש שלוש שאילתות בדיקה (א, ב, ג). להעתיק כל אחת בנפרד (בלי ה-`--` בהתחלה) ולהריץ. **כל אחת אמורה להחזיר 0 שורות.**
   - אם שאילתה **ב** מחזירה שורות, לצלם מסך ולשלוח לי. זו מדיניות ישנה שפותחת טבלה, וצריך להחליט עליה.

**מה המיגרציה עושה, במילים פשוטות:**
- מתירה במסד את ארבעת התפקידים, ודוחה כל מילה אחרת.
- נועלת את כל הטבלאות, כך שרק השרת שלנו יכול לגשת אליהן. המפתח שבדפדפן כבר לא יכול לקרוא לידים.
- נועלת את קבצי הקורסים, כך שרק השרת יכול להעלות ולמחוק.
- מוחקת סיסמאות ישנות שאולי נשארו בהגדרות.

---

## צעד 4 — הגדרות כניסה ב-Supabase (3 דקות)

**Supabase ← Authentication ← Sign In / Providers**
1. **Allow new users to sign up** ← **לכבות.** זה הצעד הכי חשוב. הכפתור במסך כבר נמחק, אבל בלי הכיבוי הזה עדיין אפשר להירשם ישירות דרך Supabase. משתמשים שפנחס יוצר במסך המשתמשים ימשיכו לעבוד.
2. **Email ← Confirm email** ← לוודא שדלוק.
3. **Minimum password length** ← 8.

**Supabase ← Authentication ← Users**
4. לעבור על הרשימה. משתמש שאינו מופיע במסך המשתמשים של ה-CRM נרשם לבד, ואפשר למחוק אותו.

---

## צעד 5 — תפקיד לכל משתמש (5 דקות)

**ב-CRM: הגדרות ← משתמשים ← ✏️ ערוך** על כל משתמש, ולבחור תפקיד:

| תפקיד | מה רואה |
|---|---|
| **מנהל** | הכל, כולל שינוי ומחיקה, משתמשים ועיצוב |
| **ניהול משרד** | הכל. בקורסים צפייה בלבד. בלי ניהול משתמשים ובלי עיצוב |
| **מזכירות** | ראשי, לידים (של כולם), משימות, צ'אט, מוצרים (צפייה), קליטה |
| **נציג מכירות** | ראשי, לידים (שלו), משימות, צ'אט |

אחרי כל שינוי: **"👁️ צפה כ..."** על אותו משתמש, ולוודא שהוא רואה רק את הלשוניות שלו.

> אם מישהו מקבל "אין לך הרשאות במערכת" — התפקיד שלו לא נשמר. לערוך אותו שוב.

## צעד 6 (לא חובה) — כפתור וואטסאפ במסך הכניסה

כדי ש"פנה למנהל" יהיה קישור וואטסאפ ישיר אליך:
**Vercel ← הפרויקט ← Settings ← Environment Variables ← Add**
- Name: `VITE_ADMIN_WHATSAPP`
- Value: המספר שלך בפורמט בינלאומי, למשל `972501234567`
- לשמור, ואז **Deployments ← Redeploy**.

בלי זה, כתוב "פנה למנהל המערכת" בלי קישור.
