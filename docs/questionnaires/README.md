## מה יש

| | |
|---|---|
| **שאלון אסטרטגיה עסקית** | 23 שאלות (20 בקישור אישי, בלי פרטי קשר), 10–15 דקות. לפני פגישת אסטרטגיה. |

**קישור אישי** — בתיק הליד או הלקוח ← לשונית "שאלונים" ← "קישור אישי ללקוח". שולחים בוואטסאפ או במייל. הקישור תקף 45 יום, אפשר למלא אותו פעם אחת, ואפשר לבטל אותו.

**קישור כללי** — `/q/strategy` ו-`/q/mental` (מופיעים בתחתית הלשונית). מי שממלא נכנס לליד הקיים לפי הטלפון או המייל. אם אין ליד כזה, נפתח ליד חדש, משויך למנהל.

**ברגע שלקוח שולח:**
1. התשובות, הציונים וקובץ PDF נשמרים בתיק הליד, ונרשמת פעילות.
2. נכתב סיכום הכנה לפגישה (Claude), אם המפתח מחובר.
3. מייל לפנחס עם ה-PDF, הציונים, הסיכום והתשובות העיקריות. ללקוח נשלח רק מייל תודה, בלי התשובות.
4. עותק PDF לדרייב: `לקוחות - שאלונים / <שם הלקוח> - <4 ספרות אחרונות של הטלפון>`.

כל שלב עצמאי. אם אחד לא מחובר או נכשל, התשובות עדיין נשמרות, ואפשר לנסות שוב מהלשונית.

## חיבור (משתני סביבה ב-Vercel)

Vercel ← הפרויקט ← Settings ← Environment Variables. אחרי הוספה: Redeploy.

### 1. מייל
| משתנה | ערך |
|---|---|
| `SMTP_HOST` / `SMTP_PORT` | שרת הדואר (אצל פנחס: `mail.pinchashorvitz.co.il`, `465`) |
| `SMTP_USER` | כתובת המייל השולחת |
| `SMTP_PASS` | הסיסמה של תיבת המייל הזו |
| `CONTRACT_NOTIFY_EMAIL` | לאן לשלוח לפנחס (לא חובה, ברירת מחדל: SMTP_USER) |

### 2. דרייב
1. נכנסים ל-script.google.com ← פרויקט חדש. קוראים לו "גשר שאלונים CRM".
2. מוחקים את מה שיש ומדביקים את התוכן של `drive-bridge.gs`.
3. ⚙️ הגדרות הפרויקט ← מסמנים "הצג את קובץ המניפסט appsscript.json" ← מדביקים בו את `appsscript.json` (זה מגביל את הסקריפט לקבצים שהוא עצמו יוצר).
4. באותו מסך, "מאפייני סקריפט" ← מוסיפים `SECRET` עם מחרוזת אקראית של 40 תווים לפחות.
5. בעורך: בוחרים את הפונקציה `setup` ← הפעלה ← מאשרים הרשאות.
6. פריסה ← פריסה חדשה ← סוג: אפליקציית אינטרנט ← הפעלה בתור: אני ← גישה: כל אחד ← פריסה. מעתיקים את הכתובת (מסתיימת ב-`/exec`).
7. ב-Vercel: `DRIVE_BRIDGE_URL` = הכתובת, `DRIVE_BRIDGE_SECRET` = אותה מחרוזת מסעיף 4.

## אבטחה ופרטיות

- **מי רואה:** רק מנהל וניהול משרד (הרשאת `questionnaires` ב-`api/_lib/permissions.ts`). נציגי מכירות ומזכירות לא רואים את הלשונית, והשרת חוסם אותם. מחיקה — מנהל בלבד.
- **אחסון:** דלי פרטי `questionnaires` ב-Supabase. אין גישה ציבורית. הורדת PDF רק דרך קישור חתום שתקף 10 דקות.
- **הקישור האישי:** 128 ביט אקראיים, תקף 45 יום, מילוי אחד בלבד. הדף הציבורי מקבל רק את סוג השאלון והשם. לא טלפון, לא מייל ולא תשובות. אחרי שליחה, הקישור מציג רק "השאלון כבר נשלח".
- **השרת לא סומך על הדפדפן:** מקבל רק שאלות מוכרות, חותך אורך, בודק שדות חובה וטווח דירוגים, ומחשב את הציונים בעצמו.
- **הגנה מספאם בקישור הכללי:** שדה נסתר לרובוטים, זמן מילוי מינימלי, ועד 6 שליחות ביום מאותה כתובת IP (נשמר רק גיבוב של ה-IP, לא ה-IP עצמו).
- **בינה מלאכותית:** נשלחות רק התשובות והשם הפרטי. בלי טלפון, מייל או כתובת.
- **מייל:** התשובות נשלחות רק לפנחס. ללקוח — מייל תודה בלי תוכן.
- **הדפים הציבוריים** לא נסרקים במנועי חיפוש (`noindex`), לא מעבירים את הקישור לאתרים אחרים (`no-referrer`), ולא נטענים בתוך אתר אחר.
- **טיוטה:** בזמן המילוי התשובות נשמרות רק במכשיר של הלקוח, ונמחקות ממנו ברגע השליחה.
- **מחיקה לבקשת לקוח:** כפתור "מחיקת השאלון והתשובות" בתצוגת התוצאות (מנהל). העותקים שכבר נשלחו למייל ולדרייב נמחקים ידנית.

## עריכת שאלות וציונים

הכל ב-`api/_lib/questionnaireDefs.ts`:
- טקסט שאלה: משנים את `label` / `hint`. **לא משנים `id`** של שאלה שכבר נענתה.
- כיוון היגד בציון: `polarity` — `1` הסכמה = חוזקה, `-1` הסכמה = קושי (מחושב הפוך), `0` לא נכנס לציון.
- ציון תחום = ממוצע ההיגדים אחרי היפוך, בסקאלה 0–100. 70 ומעלה = חוזקה, 45–69 = בינוני, מתחת ל-45 = לחיזוק.
